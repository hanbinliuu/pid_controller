# 🔒 扰动数据保留机制说明

## 📋 核心问题

**确保出现扰动后，如果没有下发新参数，扰动数据不会消失**

---

## ✅ 当前机制分析

### 1. **扰动数据存储位置**

```python
# opcua_client.py
class OPCUAClient:
    def __init__(self):
        self.collected_data = {
            loop_id: {
                'pv': [],  # PV数据列表（持续累积）
                'sv': [],  # SV数据列表
                'mv': [],  # MV数据列表
                'timestamps': []  # 时间戳列表
            }
        }
```

**特点**：
- ✅ 数据存储在内存中
- ✅ 持续累积，不会自动清空
- ✅ 只有主动调用 `clear_collected_data()` 才会清空

---

### 2. **扰动数据清空时机**

#### ❌ 不会清空的情况

```python
# 1. 手动整定失败
if disturbance_data_count < MIN_DISTURBANCE_POINTS:
    print(f"❌ 手动整定失败: 扰动数据不足")
    return False  # ← 数据保留，不清空

# 2. 数据质量不足
if not quality_check['valid']:
    print(f"❌ 手动整定失败: 数据质量不足")
    return False  # ← 数据保留，不清空

# 3. 未检测到扰动
if not is_disturbed:
    print(f"❌ 手动整定失败: 未检测到扰动")
    return False  # ← 数据保留，不清空
```

#### ✅ 会清空的情况

```python
# 只有一种情况会清空：进入扰动状态时
async def _handle_disturbance_state(self, loop_id: str):
    if 'disturbance_start_time' not in state_info:
        # 首次进入扰动状态
        await self.opcua_client.clear_collected_data(loop_id)  # ← 清空历史数据
        print(f"   🗑️  已清空历史数据")
        print(f"   📈 开始积累新扰动数据...")
```

**关键点**：
- ✅ 只在**首次进入扰动状态**时清空
- ✅ 清空后开始累积新的扰动数据
- ✅ 如果手动整定失败，数据**不会**被清空
- ✅ 用户可以**多次尝试**手动整定

## 🔍 代码验证

### 1. 数据不会自动清空

```python
# opcua_client.py
async def get_collected_data(self, loop_id: str = None, limit: int = 100):
    """获取已采集的数据"""
    if loop_id:
        if loop_id in self.collected_data:
            data = self.collected_data[loop_id]
            # 只返回最后limit个点，但原始数据不变
            return {
                'success': True,
                'data': {
                    'pv': data['pv'][-limit:],  # ← 切片，不修改原数据
                    'sv': data['sv'][-limit:],
                    'mv': data['mv'][-limit:],
                    'timestamps': data['timestamps'][-limit:]
                }
            }
```

**关键点**：
- ✅ 使用切片 `[-limit:]` 返回数据
- ✅ 原始数据 `self.collected_data[loop_id]` 不变
- ✅ 数据持续累积

### 2. 手动整定失败不清空数据

```python
# auto_tuning_system.py
async def manual_trigger_tuning(self, loop_id: str, pv_data, sv_data, mv_data):
    # 检查扰动

    # 只有下次进入扰动状态时才会清空
```

## ⚠️ 潜在问题和解决方案

### 问题1: 内存占用

**问题**：
- 数据持续累积，可能占用大量内存

**当前机制**：
```python
# opcua_client.py
MAX_DATA_POINTS = 1000  # 最大保存1000个点

async def _collect_data_task(self):
    while True:
        # 采集数据
        self.collected_data[loop_id]['pv'].append(pv_value)
        
        # 限制数据点数
        if len(self.collected_data[loop_id]['pv']) > MAX_DATA_POINTS:
            # 保留最新的1000个点
            self.collected_data[loop_id]['pv'] = \
                self.collected_data[loop_id]['pv'][-MAX_DATA_POINTS:]
```

**解决方案**：
- ✅ 已实现：限制最大数据点数为1000
- ✅ 采用滚动窗口，保留最新数据
- ✅ 1000个点 × 2秒/点 = 2000秒 ≈ 33分钟的数据

---

### 问题2: 数据过期

**问题**：
- 扰动发生后很久才手动整定，数据可能已经不准确

**建议方案**：

```python
# 添加数据时效性检查
async def manual_trigger_tuning(self, loop_id: str, pv_data, sv_data, mv_data):
    # 检查扰动数据的时效性
    state_info = self.loop_states[loop_id]
    disturbance_start_time = state_info.get('disturbance_start_time')
    
    if disturbance_start_time:
        elapsed_time = (datetime.now() - disturbance_start_time).total_seconds()
        MAX_ELAPSED_TIME = 600  # 最多10分钟
        
        if elapsed_time > MAX_ELAPSED_TIME:
            print(f"⚠️  扰动数据已过期（{elapsed_time:.0f}秒）")
            print(f"   💡 建议: 等待新的扰动或重新施加扰动")
            return False
```

## ✅ 结论

### 当前机制已经确保：

1. ✅ **扰动数据不会消失**
   - 数据存储在内存中持续累积
   - 只有主动清空才会删除
   - 手动整定失败不会清空数据

2. ✅ **可以多次尝试**
   - 第一次失败后数据保留
   - 第二次尝试时数据更多
   - 直到数据量足够为止

3. ✅ **数据持续增长**
   - 每2秒采集一个点
   - 数据点数持续增加
   - 最终一定能满足100个点的要求

4. ✅ **内存可控**
   - 限制最大1000个点
   - 采用滚动窗口
   - 不会无限增长
