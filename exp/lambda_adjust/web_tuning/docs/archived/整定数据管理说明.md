# 🔄 整定数据管理说明

## ✅ 核心要求

### 1. **必须使用扰动数据**
- ✅ 自动整定：必须检测到扰动后才触发
- ✅ 手动整定：必须检测到扰动段才能执行

### 2. **整定后清空数据**
- ✅ 每次整定完成后自动清空采集数据列表
- ✅ 为下次扰动做准备，避免旧数据干扰

## 🎯 手动整定流程

### 流程图

```
1. 用户点击"整定"按钮
   ↓
2. 获取当前采集的数据
   ↓
3. 步骤1: 扰动检测

   - 找到扰动起始位置
   ↓
4. 步骤2: 数据收集检查
   - 检查扰动数据点数量（至少100个）
   ↓
5. 步骤3: 提取纯扰动数据
   - 剔除历史稳定数据
   - 只使用扰动后的数据
   ↓
6. 步骤4: 数据质量验证
   - PV变化范围检查
   - MV变化范围检查
   - 信噪比检查
   ↓
7. 步骤5: 执行整定
   - 使用纯扰动数据
   - 计算新PID参数

   - ✅ 清空采集数据列表
   ↓
8. 进入稳定期
```

#### 手动整定入口

```python
async def manual_trigger_tuning(self, loop_id, pv_data, sv_data, mv_data):
    """手动触发整定（符合工业实际场景的优化版本）
    
    🏭 工业场景要求：
    1. 必须检测到扰动段（非稳态）
    2. 扰动后必须收集至少100个PV数据点
    3. 整定数据不能包含历史稳定数据
    4. 确保数据质量满足辨识要求
    """
    
    # 步骤1: 扰动检测
    is_disturbed, disturbance_info = await self._detect_disturbance_for_manual_tuning(
        loop_id, pv_data, sv_data
    )
    
    if not is_disturbed:
        print(f"❌ 手动整定失败: {disturbance_info['reason']}")
        return False
    
    # 步骤2: 数据收集检查
    disturbance_start_idx = disturbance_info['disturbance_start_idx']
    disturbance_data_count = len(pv_data) - disturbance_start_idx
    MIN_DISTURBANCE_POINTS = 100
    
    if disturbance_data_count < MIN_DISTURBANCE_POINTS:
        print(f"❌ 手动整定失败: 扰动数据不足")
        return False
    
    # 步骤3: 提取纯扰动数据
    pv_disturbance = pv_data[disturbance_start_idx:]
    sv_disturbance = sv_data[disturbance_start_idx:]
    mv_disturbance = mv_data[disturbance_start_idx:]
    
    print(f"   ✅ 确保100%使用扰动后的数据，不涉及历史稳定数据")
    
    # 步骤4: 数据质量验证
    quality_check = self._validate_tuning_data_quality(
        pv_disturbance, sv_disturbance, mv_disturbance
    )
    
    if not quality_check['valid']:
        print(f"❌ 手动整定失败: 数据质量不足")
        return False
    
    # 步骤5: 执行整定（使用纯扰动数据）
    success = await self._perform_auto_tuning(
        loop_id, pv_disturbance, sv_disturbance, mv_disturbance, 
        force_write=True
    )
    
    # _perform_auto_tuning 内部会清空数据
    
    return success
```

## 🗑️ 数据清空机制

### 清空时机

1. **进入扰动状态时**
   - 检测到扰动（连续3次非稳态）
   - 清空旧数据，从0开始累积新扰动数据
   - **目的**: 确保100%使用新过程特性下的数据

2. **整定完成后**
   - 自动整定完成
   - 手动整定完成
   - 清空所有采集数据
   - **目的**: 为下次扰动做准备，避免旧数据干扰

### 清空函数

**文件**: `opcua_client.py`

```python
async def clear_collected_data(self, loop_id: str):
    """
    清空指定回路的已采集数据
    用于在进入DISTURBANCE状态时重置数据，从0开始累积新的扰动数据
    
    Args:
        loop_id: 回路ID
    """
    if loop_id in self.collection_data:
        self.collection_data[loop_id] = {
            "timestamps": [],
            "pv": [],
            "sv": [],
            "mv": []
        }
        logger.info(f"🗑️  已清空回路 {loop_id} 的采集数据")
        return {"success": True, "message": "数据已清空"}
    else:
        return {"success": False, "message": "回路不存在"}
```

## 📋 数据流转示例

### 示例：自动整定完整流程

```
时间线：

T0: 系统稳定运行
    - 采集数据: [稳定数据1, 稳定数据2, ...]
    - 状态: STABLE

T1: 检测到扰动（例如：设定值变化）
    - 连续3次检测到非稳态
    - 🗑️ 清空旧数据: collection_data[loop_id] = {pv:[], sv:[], mv:[]}
    - 状态: STABLE → DISTURBANCE
    - 开始累积新数据: [扰动数据1]

T2-T100: 持续采集扰动数据
    - 采集数据: [扰动数据1, 扰动数据2, ..., 扰动数据100]
    - 状态: DISTURBANCE
    - 等待数据点数达到100个

T101: 数据充足，触发自动整定
    - 使用数据: [扰动数据1, ..., 扰动数据100]
    - 状态: DISTURBANCE → TUNING
    - 执行系统辨识
    - 计算新PID参数
    - 下发参数到OPC UA
    - 🗑️ 清空数据: collection_data[loop_id] = {pv:[], sv:[], mv:[]}
    - 状态: TUNING → STABILIZING

T102: 进入稳定期
    - 采集数据: [新参数下稳定数据1, 新参数下稳定数据2, ...]
    - 状态: STABILIZING
    - 观察新参数效果

T103: 稳定期结束
    - 状态: STABILIZING → STABLE
    - 继续监控
```

### 示例：手动整定完整流程

```
时间线：

T0: 系统稳定运行
    - 采集数据: [稳定数据1, ..., 稳定数据50]
    - 状态: STABLE

T1: 人为施加扰动（例如：调整阀门）
    - 采集数据: [稳定数据1, ..., 稳定数据50, 扰动数据1, ...]
    - 状态: STABLE（自动整定未启用，保持稳态）

T2-T150: 持续采集数据
    - 采集数据: [稳定数据1-50, 扰动数据1-100]
    - 状态: STABLE

T151: 用户点击"整定"按钮
    - 获取数据: [稳定数据1-50, 扰动数据1-100]
    - 步骤1: 扰动检测
      → 找到扰动起始位置: 索引50
    - 步骤2: 数据收集检查
      → 扰动数据点数: 100个 ✅
    - 步骤3: 提取纯扰动数据
      → 使用数据: [扰动数据1-100]（剔除稳定数据1-50）
    - 步骤4: 数据质量验证 ✅
    - 步骤5: 执行整定
      → 使用数据: [扰动数据1-100]
      → 计算新PID参数
      → 下发参数到OPC UA
      → 🗑️ 清空数据: collection_data[loop_id] = {pv:[], sv:[], mv:[]}
    - 状态: STABLE → DISTURBANCE → TUNING → STABILIZING

T152: 进入稳定期
    - 采集数据: [新参数下稳定数据1, ...]
    - 状态: STABILIZING
```
