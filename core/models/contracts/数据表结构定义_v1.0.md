# PID 智能整定 — OS 语义层表结构定义（交付文档）

> **版本**：v2.2  
> **更新日期**：2026-04-09  
> **交付方**：PID Agent 算法组  
> **接收方**：HolliCube OS 中台团队  

---

## 概述

按照 OS 数据抽象层的架构规范，当前阶段核心数据底座共计包含 **5 张表**。
本体模型（Ontology）及知识图谱的高级构建暂不在本期范围内，OS 中台本期**仅负责最底层的原始知识接入与存储**。

### 语义层 5 大模型清单

| 序号 | 表名 | 中文名 | 核心职责 | 更新频率 |
|:---|:---|:---|:---|:---|
| 1 | `os_mechanism` | **机理模型** | 回路对应的过程物理特性规则（积分/自衡等） | 静态 |
| 2 | `os_characterization` | **表征模型** | 基于历史时序算出的运行特征（卡涩、振荡等） | 跑批计算 |
| 3 | `os_data` | **数据模型** | DCS 测点映射 + 原始时序数据（PV/SV/MV） | 实时流转 |
| 4 | `os_metrics` | **指标模型** | 回路评估 KPI（自控率、稳定率等） | 定期跑批 |
| 5 | `os_knowledge` | **知识存储** | 最底层的原始知识接入（专家文档、操作规程等） | 静态 |

---

## 表 1：os_mechanism（机理模型 — 过程物理特性）

**业务指引**：明确不同回路基于物理定律的控制约束特性，是算法选择模型结构的基石。
**主键**：`loop_type`  
**API**：`GET /api/v1/mechanism/{loop_type}`

| 字段名 | 类型 | 必填 | 说明 | 示例值 (level) |
|:---|:---|:---|:---|:---|
| `loop_type` | string | ✅ | 回路类型：`level` / `flow` / `pressure` / `temperature` | `"level"` |
| `process_nature` | string | ✅ | 过程性质：`self_regulating`（自衡）/ `integrating`（积分） | `"integrating"` |
| `process_gain_sign` | int | ✅ | 固有增益符号：`+1` 正作用 / `-1` 反作用 | `1` |
| `dead_time_dominant` | bool | ✅ | 是否为大纯滞后系统 | `false` |
| `preferred_simulation_model` | string | ✅ | 算法仿真首选结构：`FOPDT` / `FO_INTEGRATOR` 等 | `"FO_INTEGRATOR"` |
| `typical_time_constant_range_s` | float[2] | | 典型时间常数范围（秒） | `[10.0, 3600.0]` |
| `mass_balance_constrained` | bool | | 是否受质量守恒约束 | `true` |

---

## 表 2：os_characterization（表征模型 — 动态运行特征）

**业务指引**：OS 中台通过定时跑批/流计算，从历史时序中挖掘出控制对象的近期运行表现。
**主键**：`device_id` + `timestamp`  
**API**：`GET /api/v1/characterization/{device_id}?hours=48`

| 字段名 | 类型 | 必填 | 说明 | 示例值 |
|:---|:---|:---|:---|:---|
| `device_id` | string | ✅ | 设备 ID | `"2216_LIC_50104"` |
| `timestamp` | string | ✅ | 特征评估截止时间 | `"2026-04-08T10:00:00Z"` |
| `oscillation_ratio` | float | | PV 振荡比例 (0~1)，越大越振荡 | `0.45` |
| `dominant_period_s` | float | | 主振荡周期（秒），0=无振荡 | `120.5` |
| `noise_level` | float | | 高频噪声强度 (0~1) | `0.02` |
| `linearity_index` | float | | 增益线性度评价 (0~1) | `0.85` |
| `stiction_index_estimated` | float | | 阀门卡涩指数估计 (0~1) | `0.15` |
| `deadband_estimated` | float | | 阀门死区估计（%） | `2.3` |

---

## 表 3：os_data（数据模型 — 测点映射与原始 PV/SV/MV 时序）

**业务指引**：整合 DCS 测点映射配置，并向算法输送**原始实时/历史的 PV、SV、MV 曲线数据**，是整个整定推理的数据粮草。  
**API**：`GET /api/v1/data/{device_id}?start_time=xxx&end_time=xxx`

### 3.1 测点映射定义（Mapping）

| 字段名 | 类型 | 必填 | 说明 | 示例值 |
|:---|:---|:---|:---|:---|
| `device_id` | string | ✅ | 设备 ID | `"2216_LIC_50104"` |
| `pv_tag` | string | ✅ | PV 测量值在 DCS 中的位号 | `"LIC-50104.PV"` |
| `sv_tag` | string | ✅ | SV 设定值在 DCS 中的位号 | `"LIC-50104.SV"` |
| `out_tag` | string | ✅ | MV/OUT 阀门输出的位号 | `"LIC-50104.OUT"` |
| `db_source` | string | ✅ | 底层 TSDB 数据源标识 | `"os_historian"` |

### 3.2 原始时序数据（Time-Series Raw Data）

> 后端请求 OS 接口时，返回结果必须携带完整的 `timestamp`、`pv`、`sv`、`mv` 四列数组。

| 字段名 | 类型 | 必填 | 说明 |
|:---|:---|:---|:---|
| `timestamp` | array(float/string) | ✅ | 时序时间戳序列 |
| `pv` | array(float) | ✅ | 被控变量历史数值 (Process Value) |
| `sv` | array(float) | ✅ | 设定值历史数值 (Set Point) |
| `mv` | array(float) | ✅ | 阀门开度/输出历史数值 (Manipulated Variable) |

**响应结构示例**：
```json
{
    "device_id": "2216_LIC_50104",
    "mapping": {
        "pv_tag": "LIC-50104.PV",
        "sv_tag": "LIC-50104.SV",
        "out_tag": "LIC-50104.OUT"
    },
    "history_data": {
        "timestamps": ["2026-04-09T08:00:00Z", "2026-04-09T08:00:10Z"],
        "pv": [50.1, 50.2],
        "sv": [50.0, 50.0],
        "mv": [32.5, 32.1]
    }
}
```

## 表 4：os_metrics（指标模型 — 回路评估）

**业务指引**：存放对回路执行日常评估而产出的宏观 KPI 数据（按天/周统计）。  
**主键**：`device_id` + `timestamp`  
**API**：`GET /api/v1/metrics/{device_id}`

| 字段名 | 类型 | 必填 | 说明 | 示例值 |
|:---|:---|:---|:---|:---|
| `device_id` | string | ✅ | 设备 ID | `"2216_LIC_50104"` |
| `timestamp` | string | ✅ | 评估周期截止时间 | `"2026-04-07T00:00:00Z"` |
| `auto_control_rate` | float | | 回路评估：自控率（%） | `92.5` |
| `stability_rate` | float | | 回路评估：稳定率（%） | `85.0` |
| `mse_score` | float | | 跟踪误差评价得分 | `3.2` |
| `intervention_count_daily` | int | | 日均干预（手动/自动投切）次数 | `3` |

---

## 表 5：os_knowledge（知识存储 — 原始知识接入）

**业务指引**：OS 中台在本期**仅负责最底层的原始知识接入**，即将控制专家的文档化经验、操作规程以及算法侧提供的默认规则模板存入数据库。  
**不涉及**：本体模型构建、知识图谱三元组抽取、大模型 RAG 等高级能力（留待后续知识图谱厂家对接）。  
**主键**：`knowledge_id`  
**API**：`GET /api/v1/knowledge/{loop_type}`

### 5.1 原始知识条目

| 字段名 | 类型 | 必填 | 说明 | 示例值 |
|:---|:---|:---|:---|:---|
| `knowledge_id` | string | ✅ | 知识条目唯一标识 | `"KN_level_001"` |
| `loop_type` | string | ✅ | 适用的回路类型 | `"level"` |
| `category` | string | ✅ | 知识分类：`constraint`（硬性约束）/ `experience`（经验备注）/ `document`（操作规程） | `"constraint"` |
| `content` | string | ✅ | 知识内容原文（纯文本） | `"液位回路严禁使用微分项（Td=0），PB 不得低于 100%"` |
| `source` | string | | 知识来源标注 | `"算法组预置模板"` |
| `doc_ref` | string | | 关联的原始文档标识或链接 | `"doc_2216_ops_manual.pdf"` |
| `created_at` | string | | 录入时间 | `"2026-04-09T00:00:00Z"` |

### 5.2 算法侧预置的默认约束参数

> 以下字段由算法组以 JSON 模板的形式提供给 OS 导入，是知识条目 `category=constraint` 的结构化呈现。

| 字段名 | 类型 | 必填 | 说明 | 示例值 (level) |
|:---|:---|:---|:---|:---|
| `td_enable` | bool | ✅ | 是否允许开启微分项 | `false` |
| `pb_range` | float[2] | ✅ | 比例带安全范围 [PB_min, PB_max] | `[100.0, 1000.0]` |
| `gain_range` | float[2] | ✅ | 过程增益合理范围 [K_min, K_max] | `[0.01, 200.0]` |
| `ti_max` | float | ✅ | 积分时间上限（秒） | `3600.0` |
| `max_overshoot_percent` | float | ✅ | 最大允许超调量（%） | `40.0` |
| `tuning_strategy` | string | ✅ | 整定策略偏好：`aggressive` / `conservative` | `"conservative"` |
| `expert_notes` | string | | 控制专家的定性经验备注 | `"液位回路：积分过程，平滑控制"` |
| `historical_best_kp` | float | | 历史最佳 Kp 推荐值 | `0.35` |
